# Лид-бот школы английского

Отдельный публичный бот-воронка: онбординг → сегментация → тест на уровень →
3 порции материалов с задержкой (квик-вин → книга → сериал) → точки конверсии
(пробный урок / лист ожидания курса по сериалам) → лёгкие чек-ины и тишина.

Архитектура ровно следует обсуждённой схеме: это **не** библиотека с меню
"выбери и скачай", а сценарий с точками возврата и разной ролью у каждого
материала.

## Структура проекта

```
lead_bot/
├── bot.py                 # точка входа: роутеры, БД, планировщик, polling
├── config.py               # все настройки/тайминги через переменные окружения
├── database.py              # SQLite: состояние каждого пользователя воронки
├── content.py                # загрузка урезанной базы материалов + обоснование выбора
├── texts.py                   # все тексты бота (персонализация по цели)
├── keyboards.py                # инлайн-клавиатуры
├── quiz.py                      # мини-тест на уровень (5 вопросов)
├── scheduler.py                  # APScheduler: кто когда получает следующую порцию
├── handlers/
│   ├── onboarding.py               # /start, вопрос про цель, выбор/тест уровня
│   ├── materials.py                 # отправка порций 1/2/3 + команда /materials
│   └── funnel.py                     # /trial, /course, /prices, /contact, /menu
├── data/
│   ├── materials_lead.json           # curated-база (9 материалов, см. ниже)
│   └── leadbot.db                     # создаётся автоматически при первом запуске
└── requirements.txt
```

## Как запустить

```bash
pip install -r requirements.txt
export BOT_TOKEN="токен_от_BotFather"          # ОБЯЗАТЕЛЬНО отдельный бот, не студенческий!
export MANAGER_USERNAME="your_manager"          # без @, для кнопки "Написать нам"
export MANAGER_CHAT_ID="123456789"               # опционально: сюда падают заявки на пробный
export PRICES_URL="https://..."                   # опционально: если нет — покажется текст-заглушка
python bot.py
```

Для GitHub-деплоя (Railway/VPS/systemd) — просто `python bot.py` в фоне,
без вебхука: бот сидит на polling, как и оригинальный. Планировщик (APScheduler)
живёт в том же процессе и не требует отдельного воркера.

### Тайминги воронки

Задаются переменными окружения (часы), по умолчанию:

| Переменная | По умолчанию | Что регулирует |
|---|---|---|
| `PORTION_2_DELAY_HOURS` | 24 | Через сколько часов после порции 1 прийдёт книга |
| `PORTION_3_DELAY_HOURS` | 48 | Через сколько часов после порции 2 прийдёт сериал |
| `FOLLOWUP_DELAY_HOURS` | 96 | Пауза между чек-инами после 3-й порции |
| `MAX_FOLLOWUPS` | 2 | Сколько чек-инов слать, потом бот замолкает |
| `SCHEDULER_INTERVAL_MINUTES` | 30 | Как часто бот проверяет базу "кому пора" |

Хранение состояния в SQLite означает, что рестарт бота (деплой, падение
процесса) не сбрасывает воронку — прогресс каждого пользователя переживает
перезапуск.

## Почему в базе именно эти 9 материалов (3 уровня × 3 штуки)

Полное обоснование — в докстринге `content.py`, коротко:

- **По одному материалу на уровень на каждую роль** в воронке: подкаст
  (быстрый вин, 5–10 минут, с самопроверкой) → книга (узнаваемая классика —
  "Алиса в стране чудес", "Портрет Дориана Грея" — работает на ощущение
  ценности) → 1-я серия сериала (не спойлерит, естественно подводит к
  групповому курсу "разбираем сериалы").
- Уровни — A1/A2/B1, потому что других в исходной базе просто нет.
- Для A2/B1 темы подкастов подобраны нейтральными ("утренняя рутина",
  "первый день на работе") — на них лучше всего ложится персонализация
  под любой сегмент (для себя / для работы / ради сериалов).
- Весь остальной объём исходной базы (десятки эпизодов, книг, подкастов)
  сознательно НЕ включён в лид-бота — это тот самый стимул "перейти в
  студенческую экосистему", про который говорили в самом начале.

Если захотите поменять конкретные материалы — правьте `data/materials_lead.json`
напрямую (структура: `{level: {podcast: {...}, book: {...}, series: {show, episode}}}`),
код их не хардкодит.

## Что дальше можно доточить

- Сейчас "персонализация по цели" — это только другой текст-обёртка вокруг
  общего пула материалов (как и обсуждали — честный компромисс для такого
  объёма базы). Если база вырастет, в `data/materials_lead.json` можно
  сделать реальные разные материалы под каждый `goal`.
- Заявки на пробный урок падают менеджеру, только если задан `MANAGER_CHAT_ID`
  (узнать свой chat_id можно через любого бота вроде @userinfobot).
- Метрики воронки (retention по дням, % дошедших до /trial и т.п.) в коде не
  считаются — сейчас это делает SQL-запрос напрямую к `data/leadbot.db`
  (таблица `users`, поля `stage`, `trial_requested`, `waitlist_joined`,
  `created_at`), но это осознанно оставлено за скобками кода бота.
